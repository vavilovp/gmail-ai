# Несколько почтовых ящиков: Gmail и обычный IMAP

Дата: 2026-11-07 · Статус: на согласовании

## Цель

Разбирать за один запуск несколько ящиков — несколько Gmail и корпоративный IMAP-ящик
(вход по логину и паролю). У каждого ящика свои настройки, категории и промпт.
Модель запускается один раз, отчёт — один общий.

**Не входит:** вход через OAuth (Microsoft 365, Google OAuth), POP3, ссылки на письма
в веб-интерфейсе корпоративной почты, параллельный разбор ящиков.

## 1. Формат config.json

```json
{
  "llm_server": { "...": "как сейчас, общий для всех ящиков" },

  "max_emails": 50,
  "categories": { "Работа": "описание", "...": "..." },
  "archive_categories": ["Реклама"],
  "fallback_category": "Прочее",
  "prompts": { "rules": [], "classify": ["..."], "digest": ["..."] },

  "accounts": [
    {
      "name": "Личный Gmail",
      "type": "gmail",
      "email": "me@gmail.com",
      "app_password": "xxxx xxxx xxxx xxxx",
      "prompts": { "rules": ["правило только для этого ящика"] }
    },
    {
      "name": "Работа",
      "type": "imap",
      "host": "mail.company.ru",
      "port": 993,
      "username": "p.vavilov@company.ru",
      "password": "...",
      "inbox": "INBOX",
      "search": "UNSEEN",
      "days": 7,
      "categories": { "Клиенты": "...", "Внутреннее": "...", "Рассылки": "...", "Прочее": "..." },
      "folders": { "Рассылки": "AI/Рассылки" },
      "prompts": { "rules": ["Письма с @company.ru — «Внутреннее»"] }
    }
  ]
}
```

### Наследование

- Любой ключ верхнего уровня (кроме `llm_server` и `accounts`) — значение по умолчанию
  для всех ящиков; такой же ключ в ящике его заменяет.
- `categories` заменяются целиком (не сливаются).
- `prompts`: `classify` и `digest` в ящике заменяют общие; `rules` **складываются** —
  сначала общие, потом правила ящика.
- `fallback_category` по умолчанию — последняя категория ящика.

### Поля ящика

| Поле | Gmail | IMAP | По умолчанию |
|---|---|---|---|
| `name` | да | да | обязательно, уникально; метка в логе/отчёте и имя файла учёта |
| `type` | `gmail` | `imap` | обязательно |
| `email`, `app_password` | да | — | обязательно для Gmail |
| `host`, `username`, `password` | — | да | обязательно для IMAP |
| `port` | — | да | 993 (SSL) |
| `inbox` | — | да | `INBOX` |
| `search` | запрос Gmail | критерии IMAP SEARCH | Gmail: как сейчас; IMAP: `UNSEEN` |
| `days` | — | да | 7 (добавляет `SINCE <дата>`; 0 — без ограничения) |
| `label_prefix`, `processed_label`, `archive_categories` | да | — | как сейчас |
| `folders` | — | да | `{}` — категория → папка для переноса |
| `max_emails`, `categories`, `fallback_category`, `prompts` | да | да | из верхнего уровня |

### Совместимость

Если `accounts` нет, а на верхнем уровне есть `email` и `app_password` — это один ящик Gmail
с `name` = адрес. Текущий `config.json` работает без изменений, поведение для него прежнее.

### Проверка конфига (до запуска модели)

Как сейчас (категории, `fallback_category`, пустые промпты) — для каждого ящика, плюс:
- `accounts` — непустой список; `name` уникальны; `type` — `gmail` или `imap`;
- обязательные поля по типу заполнены, нет заглушек `your.address` / `xxxx`;
- Gmail: `archive_categories` ⊂ `categories`; IMAP: ключи `folders` ⊂ `categories`.

Сообщение об ошибке называет ящик: «Ящик «Работа»: …».

## 2. Код и ход работы

```
gmail_ai.py        — точка входа: аргументы, консоль/окно, общий цикл (имя сохраняется)
mailai/config.py   — чтение, проверка, сборка настроек ящиков
mailai/llm.py      — llama-server, llm_call, промпты, classify, digest
mailai/mailboxes.py— интерфейс ящика, GmailBox, ImapBox
mailai/report.py   — HTML-отчёт
mailai/gui.py      — окна tkinter
tests/             — unittest, подставные IMAP и модель
```

Только стандартная библиотека Python, как сейчас.

### Интерфейс ящика

- `connect()` — подключение (3 попытки при отсутствии сети, как сейчас); ошибка входа — `Stop`.
- `pending(limit)` — id писем к разбору, от новых к старым, без уже обработанных.
- `fetch(id)` — словарь письма (`from`, `to`, `subject`, `date`, `unsub`, `body`, `link`).
- `apply(id, category) -> str | None` — разложить письмо и отметить обработанным;
  возвращает, куда письмо убрано из «Входящих» (`"архив"`, имя папки) или `None`.
  В тестовом режиме ничего не меняет, но возвращает то, что было бы сделано.
- `close()` — отключение; для IMAP также сохраняет файл учёта.

### GmailBox

Поведение как сейчас: X-GM-RAW поиск, ярлыки `label_prefix + категория` и `processed_label`,
архив категорий из `archive_categories`, ссылка `/mail/u/<email>/#all/<id>`.

### ImapBox

- Подключение `IMAP4_SSL(host, port)`, `login(username, password)`, `select(inbox)`
  (readonly в тестовом режиме).
- Поиск: `UID SEARCH <search> [SINCE <сегодня − days>]`, затем исключаются Message-ID
  из файла учёта; берутся последние `limit`.
- Чтение через `BODY.PEEK[]` — письма остаются непрочитанными. `link` пустой.
- Учёт обработанных: `state\<name>.json` — список Message-ID (если заголовка нет —
  sha1 от From+Date+Subject); хранятся последние 5000. Запись — в `close()` и после
  каждых 10 писем; в тестовом режиме не пишется.
- Перенос (если категория есть в `folders`):
  1. имя папки: `/` заменяется разделителем сервера (из `LIST "" ""`), кодируется в
     modified UTF-7;
  2. папка создаётся (`CREATE`), если её нет в `LIST`;
  3. есть `MOVE` → `UID MOVE`; иначе есть `UIDPLUS` → `UID COPY` + `+FLAGS \Deleted` +
     `UID EXPUNGE <uid>`; иначе перенос не делается, письмо остаётся во «Входящих»,
     предупреждение в лог и отчёт (одно на ящик). Общий `EXPUNGE` не используется.
- Категория без папки — письмо остаётся во «Входящих», только отмечается в учёте.

### Общий цикл

1. Загрузить и проверить конфиг (все ящики).
2. Модель: использовать запущенную или запустить (как сейчас).
3. Для каждого ящика по порядку: подключиться → разобрать письма своими категориями
   и промптом → сводка своим `digest`-промптом. Отмена проверяется перед каждым письмом.
4. Записать общий отчёт, открыть его; выключить модель, если запускали сами.

### Ошибки

- Ящик недоступен (вход, сеть) — ошибка ящика в отчёт, следующий ящик разбирается.
- Письмо не разобралось — в «Ошибки» ящика, `apply` не вызывается, письмо разберётся
  в следующий раз.
- Ошибка конфига — сразу, до запуска модели (`Stop`).
- Отмена — останавливает весь цикл; уже обработанное в IMAP сохраняется в учёт.

## 3. Отчёт

Один файл `reports\mail_<дата>_<время>[_test].html`:

1. Заголовок и плашка тестового режима.
2. Сводная таблица по ящикам: имя (якорь на раздел), писем, ждут ответа,
   убрано из «Входящих», или текст ошибки ящика.
3. Раздел каждого ящика в порядке `accounts`: заголовок «Имя (тип · адрес)», сводка модели,
   таблицы «Ждут вашего ответа», «Важное», «Остальное», «Убрано в архив» (Gmail) /
   «Перенесено в папки» (IMAP, колонка «Категория → папка»), «Ошибки».
   Без новых писем — строка «Новых писем нет».

Лог и окно прогресса: строки с префиксом `[имя ящика]`. Итог: по ящику через « · »,
например «Личный Gmail: 30 (ждут ответа 1) · Работа: 12 (ждут ответа 3)».

## Тесты

`py -m unittest` из папки проекта, без сети и модели:
- конфиг: наследование, сложение `rules`, старый формат, ошибки проверки;
- ImapBox на подставном IMAP: поиск с `SINCE`, исключение обработанных, перенос через MOVE
  и через COPY+UID EXPUNGE, создание папки, отказ без MOVE/UIDPLUS, тестовый режим;
- GmailBox: ярлыки и архив (подставной IMAP), ссылка;
- общий цикл: ошибка одного ящика не останавливает остальные;
- отчёт: разделы ящиков, сводная таблица.
