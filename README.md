# Разбор Gmail локальной моделью

Один скрипт делает всё: запускает модель → разбирает почту → открывает отчёт → выключает модель.

Для каждого непрочитанного письма модель определяет категорию, важность, нужен ли ответ и краткую суть.
Скрипт ставит ярлык `AI/<Категория>`, рекламу убирает в архив (не удаляет) и открывает HTML-отчёт
со сводкой. Письма остаются непрочитанными, обработанные помечаются ярлыком `AI/processed`.

## 1. Python

Python 3.12+, сторонние библиотеки не нужны.

```bash
winget install Python.Python.3.12
```

Проверка в PowerShell: `py --version`

## 2. Пароль приложения Gmail

- Двухэтапная аутентификация: https://myaccount.google.com/security
- Пароль приложения: https://myaccount.google.com/apppasswords

## 3. config.json

Если `config.json` ещё нет — скопируйте `config.example.json` в `config.json` и заполните `email` и `app_password`.

Если `config.json` уже есть — он продолжит работать: для отсутствующих блоков (`llm_server`, `prompts`)
возьмутся настройки по умолчанию. Чтобы их менять, скопируйте нужный блок из `config.example.json`.

`config.json` не попадает в Git (см. `.gitignore`) — в нём пароль.

В путях Windows обратная косая черта пишется двойной: `"C:\\llama\\models\\..."`

### Блок `llm_server`

| Параметр | Что это |
|---|---|
| `exe` | путь к `llama-server.exe` |
| `model` | путь к модели `.gguf` |
| `ctx_size` | контекст (131072 = 128K, 262144 = 256K) |
| `n_cpu_moe` | сколько слоёв экспертов держать в RAM (128K → 33, 256K → 36) |
| `threads` | потоки CPU |
| `port` | порт сервера |
| `extra_args` | остальные параметры llama-server |
| `startup_timeout_sec` | сколько секунд ждать загрузки модели |
| `stop_after` | выключать модель после разбора (`true`/`false`) |

### Категории (группы писем)

```json
"categories": {
  "Работа": "рабочая переписка, коллеги, клиенты, поставщики, проекты",
  "Дети": "школа, кружки, секции, родительские чаты",
  ...
},
"archive_categories": ["Реклама"],
"fallback_category": "Прочее"
```

- **Ключ** — имя категории, из него получается ярлык `AI/<Категория>`. Имя с `/` даёт вложенный ярлык
  (`"Работа/Клиенты"` → `AI/Работа/Клиенты`). Кавычки и `\` в имени нельзя.
- **Значение** — описание для модели: чем точнее, тем лучше раскладывает.
- `archive_categories` — какие категории убирать из «Входящих» в архив.
- `fallback_category` — куда класть, если модель ответила чем-то вне списка (по умолчанию — последняя категория).

Новую категорию достаточно дописать в `categories` — ярлык Gmail создаст сам при первом письме.
Ярлыки удалённых категорий в Gmail остаются, их можно удалить вручную.

### Промпты и правила разбора (блок `prompts`)

Промпты читаются из `config.json` при каждом запуске — правки действуют со следующего разбора,
код менять не нужно. Текст можно писать строкой или списком строк (строки склеиваются переводом строки).

- **`rules`** — ваши нюансы разбора, по одному правилу в строке. Добавляются в конец промпта
  как «правила пользователя», которые важнее общих указаний. Самый простой способ что-то подкрутить:

  ```json
  "rules": [
    "Письма с адресов @mycompany.ru — всегда «Работа».",
    "Письма от Тинькофф и Сбера о входе в аккаунт — важность «высокая».",
    "Чеки Яндекс Такси и Самоката — «Покупки», важность «низкая».",
    "Письма с GitHub о моих репозиториях — «Работа», о чужих — «Уведомления».",
    "Если в письме есть код подтверждения — напиши его в summary."
  ]
  ```

- **`classify`** — основной промпт разбора одного письма. Подстановка `{categories}` заменяется
  списком категорий с описаниями (если её убрать, список допишется в конец).
  Модель обязана вернуть поля `category`, `importance` (`высокая`/`средняя`/`низкая`),
  `needs_reply` и `summary` — формат ответа задаётся отдельно, промпт описывает только смысл полей.
- **`digest`** — промпт общей сводки в начале отчёта.

Проверять изменения удобно через `mail-test.bat`: в почте ничего не меняется, только отчёт.

## 4. Запуск вручную

| Файл | Что делает |
|---|---|
| `mail-test.bat` | тест в консоли: в почте ничего не меняется, только отчёт |
| `mail.bat` | разбор в консоли |
| `mail-now.bat` | как при входе в систему: окно «Разобрать почту?» и окно прогресса |

Параметры командной строки: `--dry-run`, `--limit N`, `--ask`, `--gui` (см. `py gmail_ai.py --help`).

Если модель уже запущена (например, через `start-128k.bat`), скрипт её использует и выключать не будет.

## 5. Автозапуск при входе в Windows

- `install_task.bat` — добавить задачу в Планировщик (попросит права администратора).
  Через 1 минуту после входа появится окно «Разобрать почту?».
- `remove_task.bat` — удалить задачу.

## 6. Если что-то не так

- `logs\run.log` — журнал разборов.
- `logs\llama-server.log` — журнал модели последнего запуска (ошибки загрузки и т.п.).
- Письмо, которое не удалось разобрать, попадает в раздел «Ошибки» отчёта и остаётся без ярлыка —
  при следующем запуске оно разберётся снова.
- Вернуть письмо из архива: ярлык `AI/Реклама` → «Переместить во входящие».
- Разобрать письма заново: снять с них ярлык `AI/processed`.
