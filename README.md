# Разбор Gmail локальной моделью

Один скрипт делает всё: запускает модель → разбирает почту → открывает отчёт → выключает модель.
Ящиков может быть несколько: Gmail и обычные IMAP-ящики (например, рабочая почта) — за один запуск, в один отчёт.

Для каждого непрочитанного письма модель определяет категорию, важность, нужен ли ответ и краткую суть.
В Gmail скрипт ставит ярлык `AI/<Категория>` и убирает рекламу в архив (не удаляет); в IMAP-ящике
раскладывает письма по папкам. Потом открывает HTML-отчёт со сводкой. Письма остаются непрочитанными,
обработанные помечаются (в Gmail — ярлыком `AI/processed`, в IMAP — записью в `state\`).

## 1. Python

Python 3.12+, сторонние библиотеки не нужны.

```bash
winget install Python.Python.3.12
```

Проверка в PowerShell: `py --version`

## 2. Пароль приложения Gmail

- Двухэтапная аутентификация: https://myaccount.google.com/security
- Пароль приложения: https://myaccount.google.com/apppasswords

## 3. config.json

Если `config.json` ещё нет — скопируйте `config.example.json` в `config.json` и заполните ящики в блоке
`accounts` (см. «Несколько ящиков» ниже). Лишний ящик из примера просто удалите.

Если `config.json` уже есть в старом формате (`email` и `app_password` на верхнем уровне, без `accounts`) —
он продолжит работать как один ящик Gmail: для отсутствующих блоков (`llm_server`, `prompts`)
возьмутся настройки по умолчанию. Чтобы их менять, скопируйте нужный блок из `config.example.json`.

`config.json` не попадает в Git (см. `.gitignore`) — в нём пароль.

В путях Windows обратная косая черта пишется двойной: `"C:\\llama\\models\\..."`

### Блок `llm_server`

| Параметр | Что это |
|---|---|
| `exe` | путь к `llama-server.exe` |
| `model` | путь к модели `.gguf` |
| `ctx_size` | контекст (131072 = 128K, 262144 = 256K) |
| `n_cpu_moe` | сколько слоёв экспертов держать в RAM (128K → 33, 256K → 36) |
| `threads` | потоки CPU |
| `port` | порт сервера |
| `extra_args` | остальные параметры llama-server |
| `startup_timeout_sec` | сколько секунд ждать загрузки модели |
| `stop_after` | выключать модель после разбора (`true`/`false`) |

### Несколько ящиков (блок `accounts`)

Общие настройки (`llm_server`, `max_emails`, `categories`, `archive_categories`, `fallback_category`, `prompts`)
пишутся на верхнем уровне, а ящики — списком в `accounts`:

```json
{
  "llm_server": { ... },
  "max_emails": 50,
  "categories": { "Работа": "...", "Реклама": "...", "Прочее": "..." },
  "archive_categories": ["Реклама"],
  "fallback_category": "Прочее",

  "accounts": [
    {
      "name": "Личный Gmail",
      "type": "gmail",
      "email": "your.address@gmail.com",
      "app_password": "xxxx xxxx xxxx xxxx"
    },
    {
      "name": "Работа",
      "type": "imap",
      "host": "mail.company.ru",
      "port": 993,
      "username": "your.address@company.ru",
      "password": "xxxx",
      "search": "UNSEEN",
      "days": 7,
      "categories": { "Клиенты": "...", "Внутреннее": "...", "Рассылки": "...", "Прочее": "..." },
      "folders": { "Рассылки": "AI/Рассылки" },
      "prompts": { "rules": ["Письма с адресов @company.ru — «Внутреннее»."] }
    }
  ]
}
```

Поля ящика:

| Поле | Gmail | IMAP | По умолчанию |
|---|---|---|---|
| `name` | да | да | обязательно, уникально; метка в логе и отчёте, имя файла учёта |
| `type` | `gmail` | `imap` | обязательно |
| `email`, `app_password` | да | — | обязательно для Gmail |
| `host`, `username`, `password` | — | да | обязательно для IMAP |
| `port` | — | да | 993 (SSL) |
| `inbox` | — | да | `INBOX` |
| `search` | запрос Gmail | критерии IMAP (`UNSEEN`, `FLAGGED` …) | Gmail: `in:inbox is:unread newer_than:7d -label:ai-processed`; IMAP: `UNSEEN` |
| `days` | — | да | 7 — берутся письма не старше N дней; 0 — без ограничения по дате |
| `label_prefix`, `processed_label`, `archive_categories` | да | — | `AI/`, `AI/processed`, `[]` |
| `folders` | — | да | `{}` — «категория: папка» для переноса писем |
| `max_emails`, `categories`, `fallback_category`, `prompts` | да | да | с верхнего уровня (`max_emails` — 50) |

**Наследование.** Ключ верхнего уровня — значение по умолчанию для ящиков, а такой же ключ в ящике его заменяет.
Ключи, относящиеся только к одному типу, достаются только ящикам этого типа: `email`, `app_password`, `search`,
`label_prefix`, `processed_label`, `archive_categories` — только Gmail; `host`, `port`, `username`, `password`,
`inbox`, `days`, `folders` — только IMAP. `max_emails`, `categories`, `fallback_category`, `prompts` наследуют все.
`categories` в ящике заменяются целиком, не сливаясь с общими. В `prompts` свои `classify` и `digest` заменяют общие,
а `rules` складываются: сначала общие правила, потом правила ящика.

**Что делает IMAP-ящик.**
- Письма остаются непрочитанными. Вход — только по логину и паролю; Microsoft 365 (OAuth) не поддерживается.
- Поиск: критерии `search` плюс ограничение по `days`. Ссылок на письма в отчёте для IMAP нет.
- Обработанные письма запоминаются в `state\<имя ящика>.json` по Message-ID. Удалите файл — письма
  разберутся заново. В режиме `--dry-run` файл не пишется.
- Категории из `folders` переносятся в указанные папки. Папка создаётся и подписывается автоматически;
  `/` в имени заменяется разделителем, который использует сервер. Категория без папки остаётся во «Входящих»
  (письмо только запоминается как обработанное).
- Перенос: командой MOVE, а на серверах без неё — копированием и удалением именно этого письма
  (нужна поддержка UIDPLUS). Если нет ни того, ни другого, письмо остаётся во «Входящих», а в логе и отчёте
  будет предупреждение.

**Ошибки и отчёт.** Ящик, к которому не удалось подключиться, показывается в отчёте как ошибка, остальные
разбираются дальше. Отчёт один: сводная таблица по ящикам и раздел на каждый ящик. Если новых писем нет
ни в одном ящике, отчёт не создаётся.

### Категории (группы писем)

```json
"categories": {
  "Работа": "рабочая переписка, коллеги, клиенты, поставщики, проекты",
  "Дети": "школа, кружки, секции, родительские чаты",
  ...
},
"archive_categories": ["Реклама"],
"fallback_category": "Прочее"
```

- **Ключ** — имя категории, из него получается ярлык `AI/<Категория>`. Имя с `/` даёт вложенный ярлык
  (`"Работа/Клиенты"` → `AI/Работа/Клиенты`). Кавычки и `\` в имени нельзя.
- **Значение** — описание для модели: чем точнее, тем лучше раскладывает.
- `archive_categories` — какие категории убирать из «Входящих» в архив.
- `fallback_category` — куда класть, если модель ответила чем-то вне списка (по умолчанию — последняя категория).

Новую категорию достаточно дописать в `categories` — ярлык Gmail создаст сам при первом письме
(для IMAP-ящика добавьте ещё папку в `folders`, если письма нужно переносить).
Ярлыки удалённых категорий в Gmail остаются, их можно удалить вручную.
Категории можно задать отдельно для каждого ящика (см. «Несколько ящиков»).

### Промпты и правила разбора (блок `prompts`)

Промпты читаются из `config.json` при каждом запуске — правки действуют со следующего разбора,
код менять не нужно. Текст можно писать строкой или списком строк (строки склеиваются переводом строки).

- **`rules`** — ваши нюансы разбора, по одному правилу в строке. Добавляются в конец промпта
  как «правила пользователя», которые важнее общих указаний. Правила можно писать и для отдельного ящика
  (`prompts.rules` в ящике): они добавятся к общим. Самый простой способ что-то подкрутить:

  ```json
  "rules": [
    "Письма с адресов @mycompany.ru — всегда «Работа».",
    "Письма от Тинькофф и Сбера о входе в аккаунт — важность «высокая».",
    "Чеки Яндекс Такси и Самоката — «Покупки», важность «низкая».",
    "Письма с GitHub о моих репозиториях — «Работа», о чужих — «Уведомления».",
    "Если в письме есть код подтверждения — напиши его в summary."
  ]
  ```

- **`classify`** — основной промпт разбора одного письма. Подстановка `{categories}` заменяется
  списком категорий с описаниями (если её убрать, список допишется в конец).
  Модель обязана вернуть поля `category`, `importance` (`высокая`/`средняя`/`низкая`),
  `needs_reply` и `summary` — формат ответа задаётся отдельно, промпт описывает только смысл полей.
- **`digest`** — промпт сводки по ящику (в начале его раздела отчёта).

Проверять изменения удобно через `mail-test.bat`: в почте ничего не меняется, только отчёт.

## 4. Запуск вручную

| Файл | Что делает |
|---|---|
| `mail-test.bat` | тест в консоли: в почте ничего не меняется, только отчёт |
| `mail.bat` | разбор в консоли |
| `mail-now.bat` | как при входе в систему: окно «Разобрать почту?» и окно прогресса |

Параметры командной строки: `--dry-run`, `--limit N`, `--ask`, `--gui` (см. `py gmail_ai.py --help`).

Тесты (без сети и модели): `py -m unittest` из папки проекта.

Если модель уже запущена (например, через `start-128k.bat`), скрипт её использует и выключать не будет.

## 5. Автозапуск при входе в Windows

- `install_task.bat` — добавить задачу в Планировщик (попросит права администратора).
  Через 1 минуту после входа появится окно «Разобрать почту?».
- `remove_task.bat` — удалить задачу.

## 6. Если что-то не так

- `logs\run.log` — журнал разборов; строки по ящикам начинаются с `[имя ящика]`.
- `state\<имя ящика>.json` — какие письма IMAP-ящика уже обработаны. Удалите файл — письма разберутся заново.
- `logs\llama-server.log` — журнал модели последнего запуска (ошибки загрузки и т.п.).
- Письмо, которое не удалось разобрать, попадает в раздел «Ошибки» отчёта и остаётся без ярлыка —
  при следующем запуске оно разберётся снова.
- Вернуть письмо из архива: ярлык `AI/Реклама` → «Переместить во входящие».
- Разобрать письма заново: в Gmail — снять с них ярлык `AI/processed`, в IMAP — удалить `state\<имя ящика>.json`
  (письма, перенесённые в папки, при этом нужно вернуть во «Входящие»).
- Ящик не подключился: в отчёте он будет с текстом ошибки (логин, пароль, адрес сервера), остальные ящики разобраны.
